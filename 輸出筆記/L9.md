# Lesson 9: 序列通訊 (Serial Communications)

## 1. 理論概念核心提煉 (Theoretical Core)
*   **UART (Universal Asynchronous Receiver/Transmitter)：** 異步序列通訊，不需共用時脈。
*   **資料幀結構：** 起始位元 (Start bit) -> 資料位元 (Data 8-bit) -> 停止位元 (Stop bit)。
*   **軟體序列 (SoftwareSerial)：** 利用模擬技術在一般數位腳位上實現 UART 通訊，但效能較硬體序列低。
*   **傳輸邏輯：**
    *   **TX (Transmit)：** 發送端。
    *   **RX (Receive)：** 接收端。
    *   **接線：** A 的 TX 接 B 的 RX，B 的 TX 接 A 的 RX (交叉連接)。

| 特性 | 硬體序列 (Hardware Serial) | 軟體序列 (SoftwareSerial) |
| :--- | :--- | :--- |
| 效能 | 高 (專用硬體) | 低 (CPU 運算模擬) |
| 腳位 | 固定 (Uno 為 D0, D1) | 可自訂 (但有限制) |
| 穩定性 | 高 | 高鮑率時易出錯 |

## 2. 實作導向與範例程式碼 (Implementation & Code)
```cpp
#include <SoftwareSerial.h>

SoftwareSerial mySerial(10, 11); // RX, TX

void setup() {
  Serial.begin(9600);   // 硬體序列 (與電腦通訊)
  mySerial.begin(9600); // 軟體序列 (與另一台 Arduino 通訊)
  Serial.println("System Ready");
}

void loop() {
  // 從硬體序列轉發到軟體序列
  if (Serial.available()) {
    char c = Serial.read();
    mySerial.print(c);
  }
  
  // 從軟體序列轉發到硬體序列
  if (mySerial.available()) {
    char c = mySerial.read();
    Serial.print(c);
  }
}
```
*   **硬體接線：**
    *   Arduino A D10 (RX) -> Arduino B D11 (TX)。
    *   Arduino A D11 (TX) -> Arduino B D10 (RX)。
    *   **GND 必須相連。**

## 3. 實用性延伸與業界實務 (Extended Concepts)
*   **技術延伸：**
    *   **同位檢查 (Parity Bit)：** 用於簡單的偵錯，確保資料傳輸正確性。
*   **業界實務：**
    *   **RS-232 / RS-485：** UART 僅為通訊協定，業界常透過收發器晶片轉換為高電壓的 RS-232 或差分訊號的 RS-485 以進行長距離傳輸。

## 4. 潛在考點與硬體陷阱標記 (Pitfalls)
*   **硬體陷阱：**
    *   **邏輯電位不匹配：** 5V Arduino 與 3.3V 設備 (如 ESP8266) 通訊時，必須分壓或轉換電位。
    *   **Buffer 溢位：** 若讀取速度低於發送速度，序列緩衝區會滿溢導致丟失資料。
*   > ⚠️ **重要考點：** UART 通訊中，傳收雙方唯一必須達成共識的硬體設定是什麼？(答：Baud Rate)。

---
### 實作設定三步驟 Checklist
1. 確認交叉接線 (TX-RX, RX-TX) 與共地 (GND)。
2. 統一雙方的 `Baud Rate`。
3. 使用 `Serial.available()` 檢查是否有新資料後再讀取。
