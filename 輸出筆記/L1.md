# Lesson 1: Arduino 介紹與基礎偵錯

## 1. 理論概念核心提煉 (Theoretical Core)
*   **Arduino 硬體架構：**
    *   核心為 **ATmega328P** 微處理器 (8-bit AVR)。
    *   包含 14 個數位 I/O (6 個支援 PWM) 與 6 個類比輸入。
    *   運作電壓 5V，時脈 16MHz。
*   **麵包板 (Breadboard) 原理：**
    *   **電源軌 (Power Rails)：** 兩側紅藍線處，縱向連通，通常用於 VCC 與 GND。
    *   **終端條 (Terminal Strips)：** 中間區域橫向連通 (A-E 與 F-J 各自連通)，中間有溝槽隔開。
*   **偵錯機制 (Debugging)：**
    *   **序列通訊 (UART)：** 透過 USB 轉 TTL 晶片進行資料傳輸。
    *   **Baud Rate (鮑率)：** 每秒傳輸位元數 (如 9600, 115200)，傳收雙方必須一致。

## 2. 實作導向與範例程式碼 (Implementation & Code)
```cpp
void setup() {
  // 初始化序列通訊，設定傳輸率為 9600 bps
  // 底層配置：設定 UBRR0 暫存器以決定 Baud Rate，並致能 TX/RX
  Serial.begin(9600); 
}

void loop() {
  int sensorValue = analogRead(A0); // 讀取類比腳位 A0 (0-1023)
  
  // 輸出偵錯訊息
  Serial.print("Current Sensor Value: "); 
  Serial.println(sensorValue); // println 會在結尾加上換行符號 (\n\r)
  
  delay(500); // 延遲 500ms
}
```
*   **底層暫存器剖析：**
    *   `Serial.begin()`：修改 `UCSR0B` (致能 TXEN0, RXEN0) 與 `UCSR0C` (設定資料位元、停止位元)。
*   **硬體接線：**
    *   LED 陽極 (長腳) -> 電阻 -> 數位腳位 (D13)。
    *   LED 陰極 (短腳) -> GND。

## 3. 實用性延伸與業界實務 (Extended Concepts)
*   **技術延伸：**
    *   **硬體偵錯器 (In-Circuit Debugger)：** 業界常使用 JTAG 或 SWD 介面，可進行單步執行 (Step) 與觀察記憶體。
*   **業界實務：**
    *   **條件編譯：** 使用 `#define DEBUG` 配合 `#ifdef`，在正式出貨版 (Release) 移除 `Serial.print` 以節省空間並提高效能。

## 4. 潛在考點與硬體陷阱標記 (Pitfalls)
*   **硬體陷阱：**
    *   **TX/RX 衝突：** 上傳程式時若 D0/D1 接有其他裝置，常導致上傳失敗。
    *   **共地 (Common Ground)：** 不同電源供電的模組間，GND 必須相連，否則訊號會因參考點不同而異常。
*   > ⚠️ **重要考點：** 麵包板中間的溝槽設計目的為何？(答：為了跨接 IC 元件，防止兩側腳位短路)。

### 實作設定四步驟 Checklist
1. 確認 Arduino 開發板型號與 COM Port 連接正常。
2. 在 `setup()` 中呼叫 `Serial.begin()` 設定通訊速率。
3. 程式中插入 `Serial.println(var)` 觀察關鍵變數。
4. 開啟 Serial Monitor 並確保右下角 Baud Rate 設定一致。
